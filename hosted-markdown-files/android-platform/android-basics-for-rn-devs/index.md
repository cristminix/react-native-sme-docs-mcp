# Android Basics for RN Devs

Android Studio, `adb`, and Gradle - the minimum native Android literacy every React Native developer needs without becoming a full-time Android engineer. On Expo SDK 57 you spend most days in JavaScript; this page is the map for when builds break, permissions misbehave, or Play Console asks questions Gradle can answer.

Highlights / Android Basics for RN Devs

* You rarely edit Gradle by hand in Expo CNG - config plugins and prebuild own the native project
* adb is the RN dev's terminal: devices, logcat, port reverse, and APK install
* settings.gradle registers modules; app/build.gradle is where app-level deps and signing live
* Run npx expo run:android instead of opening Android Studio for day-to-day JS work
* JAVA\_HOME and ANDROID\_HOME must point at JDK 17 and the Android SDK - wrong paths cause cryptic Gradle failures

## Recipe

> Quick-reference recipe card - copy-paste ready.

```bash
# Verify toolchain before any native build
java -version          # expect 17.x (Temurin or Android Studio bundled JDK)
echo $ANDROID_HOME     # ~/Library/Android/sdk on macOS default install
 
# List devices and start Metro-backed debug build
adb devices
npx expo run:android
 
# Tail React Native + app logs (filter noise)
adb logcat '*:S' ReactNative:V ReactNativeJS:V AndroidRuntime:E
 
# Reverse Metro port when USB debugging (Wi-Fi dev client uses LAN IP instead)
adb reverse tcp:8081 tcp:8081
 
# Regenerate android/ from app.config (CNG workflow)
npx expo prebuild --platform android
```

```text
android/                          # generated by prebuild - treat as build output in CNG
├── settings.gradle               # includes app module + autolinked native libs
├── build.gradle                  # root project plugins (AGP, Kotlin)
├── gradle.properties             # JVM args, New Arch flags, caching toggles
└── app/
    ├── build.gradle              # applicationId, SDK versions, dependencies, signing
    └── src/main/
        ├── AndroidManifest.xml   # permissions, intent filters (from app.config)
        └── java/.../MainActivity.kt
```

**When to reach for this:**

* First `npx expo run:android` fails with JDK or SDK path errors.
* You need logcat to debug a native crash that never reaches the JS redbox.
* A teammate asks why `android/` exists and whether to commit it.
* You are tracing where a manifest permission or Gradle dependency came from.

## Working Example

**Step 1 - Confirm environment**

```bash
# macOS - typical Android Studio install paths
export ANDROID_HOME="$HOME/Library/Android/sdk"
export PATH="$PATH:$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator"
 
# Expo SDK 57 / RN 0.86 expects JDK 17
/usr/libexec/java_home -V
export JAVA_HOME=$(/usr/libexec/java_home -v 17)
 
npx expo-doctor
```

**Step 2 - Run on emulator or USB device**

```bash
# Start a recent API image (API 34–35) - not API 28 museum pieces
emulator -list-avds
emulator -avd Pixel_8_API_35 &
 
adb wait-for-device
npx expo run:android
```

**Step 3 - Debug a white screen**

```bash
# Terminal 1 - Metro already started by run:android; or:
npx expo start --dev-client
 
# Terminal 2 - native + JS logs
adb logcat '*:S' ReactNativeJS:V ReactNative:V SoLoader:E AndroidRuntime:E
```

**Step 4 - Install a CI/EAS APK locally**

```bash
adb install -r ./build.apk
adb shell am start -n com.example.shopapp/.MainActivity
```

**What this demonstrates:**

* **`adb devices`** - one authorized device/emulator before Gradle deploys.
* **`adb reverse`** - USB device reaches Metro on `localhost:8081`.
* **`logcat` filters** - surface JS `console.log` and native stack traces.
* **`android/` layout** - know which file to inspect vs which to regenerate with prebuild.

## Deep Dive

### How It Works

* **Expo CNG (Continuous Native Generation)** generates `android/` from `app.config.ts` + config plugins. You edit config, not hand-merge `build.gradle` on every upgrade.
* **`npx expo run:android`** invokes Gradle (`:app:installDebug`), installs the debug APK, and launches the dev client or debug build.
* **Autolinking** (via `expo-modules-autolinking`) injects native modules into `settings.gradle` - you do not manually `include` each library.
* **Android Studio** is for inspecting layouts, profiling, and editing Kotlin when you ship custom native code - not for daily JS iteration.
* **`adb`** bridges host machine and device: shell, file push/pull, intents, port forwarding.

### Gradle Mental Model

| File | Role | RN dev touch frequency |
| --- | --- | --- |
| `settings.gradle` | Declares included modules (`:app`, autolinked libs) | Rare - prebuild/plugin |
| Root `build.gradle` | AGP version, shared repos | Rare |
| `app/build.gradle` | `applicationId`, `minSdk`, `targetSdk`, deps, signing | Occasional via plugin |
| `gradle.properties` | JVM heap, `newArchEnabled`, caching | Tuning builds |
| `AndroidManifest.xml` | Permissions, activities, intent filters | Via `app.config` / plugins |

```gradle
// app/build.gradle (simplified mental model - actual file is prebuild-generated)
android {
    namespace "com.example.shopapp"
    defaultConfig {
        applicationId "com.example.shopapp"
        minSdkVersion rootProject.ext.minSdkVersion
        targetSdkVersion rootProject.ext.targetSdkVersion
    }
}
dependencies {
    implementation("com.facebook.react:react-android")
    // autolinked Expo modules appear here after prebuild
}
```

### Android Studio Essentials

| Task | Where in Android Studio |
| --- | --- |
| Open generated project | **File → Open** → `android/` folder |
| Sync Gradle | Elephant icon / **File → Sync Project with Gradle Files** |
| View merged manifest | **app → manifests → AndroidManifest.xml (Merged)** |
| Device Manager | **Tools → Device Manager** - create API 35 AVD |
| Logcat UI | **View → Tool Windows → Logcat** - same data as CLI |

You do **not** need Android Studio running for `npx expo run:android` - only the SDK + platform-tools on `PATH`.

### adb Commands RN Devs Use Weekly

| Command | Purpose |
| --- | --- |
| `adb devices` | List connected emulators/phones |
| `adb logcat` | Stream system and app logs |
| `adb reverse tcp:8081 tcp:8081` | USB → Metro |
| `adb install -r app.apk` | Sideload release/internal build |
| `adb shell pm clear com.pkg` | Reset app data (fresh permission prompts) |
| `adb shell am force-stop com.pkg` | Kill app process |
| `adb shell dumpsys package com.pkg` | Inspect granted permissions |

### CNG vs Committed `android/`

| Workflow | Commit `android/`? | Upgrade path |
| --- | --- | --- |
| Managed + EAS Build (no prebuild locally) | No | `eas build` runs prebuild in cloud |
| Local `expo run:android` | Optional - often gitignored | `npx expo prebuild --clean` on SDK bump |
| Bare / heavy native customization | Yes | Manual merge + plugins |

SDK 57 teams usually **gitignore** `android/` and regenerate - see [Prebuild Basics](https://docs.wahwei/reactnative.codeguides.io/cng-prebuild/prebuild-basics/).

## Gotchas

* **Wrong JDK version** - AGP 8.x requires JDK 17; JDK 8 or 21 mismatches produce opaque "Could not resolve" errors. **Fix:** `export JAVA_HOME` to 17 before Gradle.
* **ANDROID\_HOME unset** - `sdkmanager` and Gradle cannot find build-tools. **Fix:** Point at Android Studio SDK path; add `platform-tools` to `PATH`.
* **Editing `android/` without a plugin** - Next `prebuild --clean` wipes manual edits. **Fix:** Move changes to a config plugin or `expo-build-properties`.
* **Ancient emulator API level** - API 24 emulators hide edge-to-edge, photo picker, and permission changes in RN 0.86. **Fix:** Test on API 34–35 images.
* **`adb device unauthorized`** - RSA fingerprint not accepted on phone. **Fix:** Revoke USB debugging authorizations on device; replug and accept prompt.
* **Assuming Android Studio Run ▶ replaces Expo** - Studio builds its own variant; Metro may not attach. **Fix:** Use `npx expo run:android` for dev-client workflow.

## Alternatives

| Alternative | Use When | Don't Use When |
| --- | --- | --- |
| EAS Build only (no local `android/`) | Team has no Android laptops | You need daily native debugging |
| Android Studio Logcat UI | Visual filtering, multi-process | Headless CI - use CLI `adb logcat` |
| `expo start` + Expo Go | Quick JS-only spikes on SDK 54 | SDK 57 dev clients with custom native modules |
| Physical device over Wi-Fi | USB port contention | Corporate networks block mDNS |

## FAQs

Do I need Android Studio installed?

* You need the **Android SDK** and **platform-tools** (`adb`). Android Studio is the easiest installer on macOS/Windows.
* Daily JS work uses VS Code/Cursor + terminal - Studio is for native inspection and profiling.

Why does my project have no android/ folder?

* Managed Expo workflow generates native projects at build time (`eas build` or `npx expo prebuild`).
* Run `npx expo prebuild --platform android` when you need local Gradle builds.

What is applicationId vs package name?

* `applicationId` in Gradle is the Play Store identity (`com.example.shopapp`).
* Kotlin package paths under `java/com/example/...` can differ in advanced setups - keep them aligned in Expo config (`android.package`).

How do I find my app's package name?

* `app.config.ts` → `expo.android.package`.
* Or `adb shell pm list packages | grep shop`.

Where do manifest permissions come from?

* Expo modules and `app.config` plugins merge permissions into `AndroidManifest.xml` at prebuild.
* Inspect merged manifest in Android Studio to see the final list.

Can I use Windows for Android development?

* Yes - Android is first-class on Windows. Set `ANDROID_HOME`, use JDK 17, enable Hyper-V/WSL2 for emulators.
* iOS builds still require macOS; Android-only devs are common on Windows/Linux.

What Gradle task does expo run:android execute?

* Typically `:app:installDebug` on the debug variant, then launches the main activity.
* Pass `--variant release` only when intentionally testing release builds locally.

How do I clear Gradle corruption?

* `cd android && ./gradlew clean` then rebuild.
* Nuclear: delete `android/`, run `npx expo prebuild --clean --platform android`.

Does New Architecture change the Gradle layout?

* `newArchEnabled=true` in `gradle.properties` toggles Fabric/TurboModules - default on RN 0.86.
* Folder layout is unchanged; native deps must ship New Arch-compatible binaries.

How does this relate to Play Console?

* Gradle produces the AAB/APK; Play Console consumes it. Signing and tracks are separate - see [Signing & Play App Signing](https://docs.wahwei/reactnative.codeguides.io/android-platform/signing-and-play-app-signing/) and [Internal Testing Tracks](https://docs.wahwei/reactnative.codeguides.io/android-platform/internal-testing-tracks/).
